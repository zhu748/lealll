# 第三轮：网络桥接、内存限额与后台生命周期

本轮基于[第二轮工作树](review-round2-2026-10-26.md)继续优化。目标是分离验证码求解器的宿主基础设施，修复可独立复现的资源问题；版本、依赖和锁文件保持不变。

## 审查发现与修复

| 问题 | 影响 | 改动 |
| --- | --- | --- |
| 同步 HTTP worker 用 `arrayBuffer()` 完整接收响应，再拷入 8 MiB 共享区 | 共享区大小没有限制下载过程的内存；大响应直到下载完成才失败 | 增量读取并直接写入共享区，元数据和正文共用严格容量限额 |
| `Atomics.wait()` 接收未经校验的超时 | NaN 会被当作无限等待，卡住调用线程 | 统一校验超时，默认 12 秒，限制平台计时器溢出 |
| 超时只结束宿主等待，没有终止 worker | 旧请求及其线程可能继续存活，下一次调用复用繁忙 worker | 宿主超时终止并清空 worker；worker 同时通过 AbortController 约束网络与正文读取 |
| worker 错误诊断也可能超过共享区 | 写错误本身可能失败，无法正常通知宿主 | 错误信息最多编码 4 KiB；发布状态并唤醒后再做清理 |
| 预热异步加载/启动在 stop 后继续完成 | 已停止的代理可能重新启动池；旧任务清理也可能影响后续实例 | 统一控制器管理代次、串行启动、立即停止和过期任务清理 |
| 服务的备用账号预热分支没有保存模块句柄 | 关闭时不能通过原有句柄停止这条路径启动的池 | 所有预热分支共用生命周期控制器 |
| 异步拦截与诊断仍完整缓冲上游响应 | 大响应没有实际的流式限额 | 共用有界响应读取工具，超过 8 MiB 取消上游并释放 reader |
| `fetchAndStore()` 没有调用方 | 其中的 5 MiB 检查看起来像有效保护，实际没有覆盖活跃读取路径 | 删除该私有死代码，给实际调用路径接入限额 |

## 代码分类

| 模块 | 职责 |
| --- | --- |
| `src/proxy/captcha-sync-fetch.ts` | 同步桥接宿主：创建、复用、超时终止和关闭 worker |
| `src/proxy/captcha-sync-worker.ts` | 具有完整 TypeScript 类型的独立 worker 程序；通过自身函数源码嵌入，运行依赖在程序内部获取 |
| `src/proxy/captcha-sync-protocol.ts` | 共享内存布局、请求/响应类型、超时规范化和结果校验 |
| `src/utils/response-body.ts` | 有界上游正文读取、超限取消与 reader 释放 |
| `src/runtime/captcha-runtime.ts` | 延迟加载与跨启停任务所有权，供 serve、Android、TUI 共用 |

`captcha-happy.ts` 从 **2603 行减至 2460 行**。桥接代码从 `@ts-nocheck` 文件移入严格检查模块，worker 程序也作为 TypeScript 函数检查，而不是维护一段不受类型检查的 JavaScript 字符串。其余 DOM/guest 部分仍保留原有 `@ts-nocheck`，没有声称完成整个求解器的类型化。新增模块和测试仍计入项目总代码量。

## 行为与资源边界

- 同步桥接仍通过线程与 SharedArrayBuffer 工作，不需要子进程、独立 worker 文件或额外网络依赖。成功响应保留原有 status、statusText、headers、setCookie 和 Buffer 正文形状。
- 同步共享负载限制为 **8 MiB，包含元数据与正文**；异步拦截/诊断的正文限制为 **8 MiB**。这约束应用保留的响应数据，不是整个进程 RSS 的硬上限，也不包括传输栈已经收到的单个数据块。
- 宿主返回的 Buffer 继续拥有独立正文副本，不持有共享内存视图。空闲 worker 使用 `unref()`，窗口销毁和同步超时仍显式终止它。
- 默认同步超时 **12 秒**。无效、非正、非有限值回退默认；有效值向上取整并限制在平台计时器范围。实际超时后旧线程不会被下次请求复用，旧线程退出事件也不会清除新线程引用。
- 上游 HTTP 错误仍作为 HTTP 响应返回；容量、网络、超时及协议失败通过既有 `{ error }` 形状返回，调用方沿用原错误处理。
- 停止后台池会立即清理当前资源。若启动正在等待加载/配置，完成后会检查代次；已经过期的启动不会保留新工作。替换启动串行执行，保证旧清理先于新启动，代价是重启预热可能等待上一次异步启动结束。
- TUI 清理时停止自己持有的池和领取调度器；领取模块加载完成前已关闭 TUI 时，不再启动调度器。

## 开发检查入口

```bash
bun run typecheck
bun run test:offline
bun scripts/sync-fetch-smoke.ts
bun run build:android-bundle
python3 scripts/cli-smoke.py
python3 scripts/android-smoke.py
```

同步桥接 worker 函数必须保持自包含：类型导入会被编译移除，运行时依赖通过参数传入的 require 在函数内部获取。普通与 minify 打包冒烟用于防止未来重构引入未被序列化的闭包依赖。传入需要同步桥接的本机服务时，服务必须运行在另一个线程或进程，否则调用线程被 Atomics.wait 阻塞会造成测试自身死锁。
