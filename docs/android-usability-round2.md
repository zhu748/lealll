# Android APK 第二轮可用性优化

本轮继续改进后台服务控制、更新检查的生命周期与网络等待，以及窄屏和手动主题下的可读性。保留已有包名、配置、凭据格式和更新偏好键。

## 使用行为

- 设置页提供后台服务的停止、重启和恢复入口，未允许通知时也能关闭整个后台服务。执行前说明会中断连接及未完成的授权，配置和已保存的登录凭据会保留。重启会重新读取配置，完成后需手动启动代理。
- 停止时显示「停止中」，旧进程退出后才显示「已停止」。重启先等待旧进程退出，再启动替代进程，避免旧代理端口尚未释放时发生冲突。等待超时会报告错误，不把仍在运行的进程当作已退出。
- 主动停止服务后，旋转屏幕不会自动启动服务。再次正常打开应用或点击「启动服务」可以恢复；主页标题能区分已停止、停止中和启动失败。
- 更新检查、检查结果及弹窗由独立 ViewModel 保留。旋转屏幕、重复点击不会重复发起同一检查；关闭后的弹窗不会因重建界面再次出现。手动检查仍可查看已忽略的版本，自动检查开关与忽略标签继续持久化。
- 检查更新失败会清除旧的成功结果，设置页能显示本次失败。异常资产条目会跳过，并从有效 HTTPS APK 链接中优先选择 release；无效、溢出的版本号不会触发升级提示。
- 服务商、套餐和主题选项在可用宽度不足时换行。成功、警告和弱提示文字的颜色跟随实际生效的应用主题，修复手动亮色/暗色与系统主题不一致时的配色问题。

## 代码职责

| 模块 | 职责 |
| --- | --- |
| `update/UpdateChecker.kt` | Release 元数据解析和版本比较 |
| `update/ReleaseClient.kt`、`UpdatePrefs.kt` | GitHub 请求及更新偏好 |
| `ui/UpdateViewModel.kt`、`UpdateDialog.kt` | 保留更新状态、单次请求、消息与弹窗 |
| `ui/ServiceActionDialog.kt` | 后台服务操作确认，使用枚举代替字符串动作 |
| `http/JsonHttpTransport.kt`、`BoundedResponse.kt` | 共享网络连接、请求取消、整次超时与响应体上限 |
| `ProcessShutdown.kt` | 幂等异步停止和有时限的退出等待 |
| `ServerService.kt` | 进程会话、前台通知和启动/停止状态 |
| `MainActivity.kt` | 权限、生命周期及页面组合 |

本地控制与 GitHub 检查共用 OkHttp 4.12.0。每次请求限制整个 HTTP 调用的时长，而非只限制单次读取；响应按 UTF-8 字节读取，解码后的正文最多 1 MiB。取消协程或关闭控制会话会取消正在执行的 HTTP call。禁止重定向和自动网络重试，避免控制命令被自动重放。

状态和日志仍为 2 秒、普通控制操作为 15 秒、额度为 25 秒；更新检查为 12 秒。未增加上游额度轮询。整次超时的语义参见 [OkHttp 官方文档](https://square.github.io/okhttp/4.x/okhttp/okhttp3/-ok-http-client/-builder/call-timeout.html)。

原版本检查脚本仍寻找已经移走的 `src/index.ts` 版本常量，现改为读取 `src/version.ts` 的共享导出；可使用 Node.js 24+ 或 Bun 执行。
