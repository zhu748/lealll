# 性能与代码分类优化记录

本轮基于 `1c3bdbc`，检查了请求路由、凭证选择、同步和闲时代理、流式转换、后台统计、Responses 缓存以及 Android 共用的 Node 服务入口。优化集中在请求频繁经过的 CPU 和内存路径；原有后台、多账号、代理池、验证码、MCP、闲时通道、领取和 Responses 功能继续使用现有接口。

## 项目职责与本轮范围

| 目录 | 职责 | 本轮处理 |
| --- | --- | --- |
| `src/server`、`src/admin` | HTTP 路由、面板与管理 API | 保留路由；优化统计容量管理 |
| `src/auth`、`src/config` | 凭证、账号存储与配置 | 复核现有缓存及凭证模式；保留存储与配置格式 |
| `src/proxy` | 请求准备、传输、重试、代理池、验证码 | 提取请求体处理、代理池类型、来源读取与选择策略 |
| `src/translator`、`src/responses` | 协议转换与会话历史 | 共用增量 SSE 分帧与单事件解析；保留 Responses 存储接口 |
| `src/async`、`src/mcp`、`src/claim` | 闲时通道、MCP 与领取 | 闲时通道共用请求体读取和分帧；保留其他协议行为 |
| `src/runtime`、`Android-APP` | Bun/Node 兼容及 Android 宿主 | 验证 Node 服务包运行；本轮未改 Kotlin 界面 |

## 性能修改

1. **代理池复用工作代理。** 原实现每次 `pickProxy()` 都遍历全部代理构造 URL 集合，再线性查找工作代理。现在按代理数组身份复用 URL 索引，热路径使用 Map 查询。代理集合变更后更新索引，清空池、切换存储目录或持久化失败时释放旧索引。故障计数仍更新同一个代理对象，沿用原有互斥和延迟落盘规则。
2. **代理轮换只做一次搜索。** 合并“是否存在可用代理”的预扫描和轮换扫描，优先选择未冷却且未排除的代理；全部处于冷却期时保留第一个未排除的候选。排除集合、轮换顺序和工作代理保持规则继续执行。
3. **账号统计用 Map 顺序维护 LRU。** 原实现每次记录都调用 `Object.keys()` 检查账号表大小，超限时再排序。现在按 Map 顺序维护最近使用位置，超限直接删除最旧项。模型容量检查复用已有 Map 的大小。统计去重、迟到重试、成功/失败重分类和额度汇总规则继续由原测试覆盖。
4. **增量 SSE 分帧。** 新 `SSEFramer` 只扫描新文本，事件完成时拼接片段一次。普通 LF 完整事件直接切片，避免逐行分配；CR、CRLF、混合换行和跨读取边界使用状态机处理。同步双向转换、Responses 流、闲时 OpenAI 适配及统计观察器共用此实现。
5. **减少流式解析分配。** 已分帧的数据使用 `parseSSEEvent()` 解析一个事件，省去再次拆帧和事件数组。`extractSSEData()` 统一多行 data 字段读取，统计仍先检查感兴趣的标记，再决定是否解析 JSON。
6. **减少请求与来源读取的复制。** 同步、Responses 和闲时请求复用 `readRequestBytes()`，单块请求无需额外拼接。代理来源按流式 TextDecoder 解码，再拼接文本，省去完整二进制缓冲区的再复制。请求体正常完成、超限和读取失败都释放 reader。
7. **闲时适配器使用迭代读取。** 将递归 Promise pump 改成循环，保留 keepalive、错误事件和完成标记；结束或失败时清理上游 reader。

## 性能实测

使用 Bun **1.4.0**，同一环境、同一脚本分别加载原始提交和优化工作树。每个场景先预热，再运行五次，取中位数。请求与代理均为本机模拟数据，没有真实上游调用。原始数据保存在 [performance-benchmarks.json](performance-benchmarks.json)。

| 场景 | 原版本 | 优化后 | 解释 |
| --- | ---: | ---: | --- |
| 5000 条代理，连续复用工作代理 5000 次 | 1304.315 ms | 3.459 ms | 消除每次请求的全池集合构建和查找 |
| 1000 个账号，记录 10000 条统计 | 262.905 ms | 10.799 ms | 消除每次记录的账号表遍历 |
| 512 KiB 单事件，256 字节分片，完整 SSE 转换 | 103.793 ms | 3.042 ms | 消除未完成事件的重复扫描 |
| 10000 个短事件，16 KiB 网络块，完整 SSE 转换 | 23.747 ms | 23.415 ms | 基本持平，差异视为测量波动 |

这些数字衡量指定场景的本地处理开销，不能推导成模型生成速度或整站吞吐量的同等提升。普通短事件场景作为对照，避免仅展示大事件场景。

复现当前版本：

```bash
bun run --preload ./scripts/test-local-only.ts ./scripts/bench-hotpaths.ts
```

对比另一个装有相同依赖的 checkout：

```bash
bun run --preload ./scripts/test-local-only.ts ./scripts/bench-hotpaths.ts /path/to/baseline
```

## 行为边界

- 翻译流单事件的默认缓存限制为 **1 MiB**，按 UTF-8 字节计量。超限后取消上游并返回流错误，避免无终止事件无限增长。原有常量现在由这些流式转换路径统一执行。
- 透传统计超过观察限制时只停止统计解析，原始响应字节继续传给客户端。压缩响应仍不作为明文 SSE 解析。
- 上游结束时刷新 TextDecoder，并处理缺少最后空行的事件。Responses 流解析失败会进入现有失败事件路径；失败或取消的响应不写入完成历史。
- 请求体超限继续返回 413，同时保留“不取消 Node 请求源”的行为，避免 Bun HTTP 适配器提前提交空 200；reader 锁会正常释放。
- 验证码生命周期测试显式提供空 Cookie 与内存 HTML，实际验证 guest 定时器和 teardown，不再加载远程 SDK。生产 `createDom()` 默认仍使用原 Cookie 与页面。

## 后续可继续整理的区域

`auth/store.ts` 的加密、账号操作和导入导出仍集中在一个大文件；`captcha-happy.ts` 的 DOM、网络拦截和诊断也值得按职责拆分。代理池的持久化/检测任务及主代理的传输/重试可以继续分离。Responses 缓存插入时还会遍历 TTL 记录，后续优化需同时覆盖 LRU 顺序、替换、字节预算和时间变化。这些区域本轮保留现有实现及测试。
