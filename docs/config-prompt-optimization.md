# 配置保存与提示词处理完善记录

本轮基于 `d56cc80`（v4.8.2-fork.1），重点检查管理 API 的配置生命周期、提示词处理热点、Responses 请求与响应转换，以及 Android 共用的 Node 服务入口。现有三条默认规则、协议路径、多账号和其他功能保留。

## 已修复的问题

| 场景 | 原行为 | 改进后 |
| --- | --- | --- |
| 同时保存重试参数、提示词和端点 | 仅 YAML 写入串行，草稿按旧状态生成，后一次保存可能覆盖前一次 | 合并、写入和热更新共用同一队列，读取前一次成功后的状态 |
| 修改监听地址后继续保存其他设置 | 从运行地址生成 YAML，覆盖已经保存的待重启地址 | 保留已保存的端口与地址；GET 配置返回保存值；运行地址在进程重启后生效 |
| 端点、路由、映射或 thinking 配置保存失败 | 文件写入失败前已经修改运行状态 | 在隔离草稿上修改，文件写入成功后才热更新 |
| 账号切换与设置保存并发 | 计划与认证同步可能被旧配置覆盖 | 活跃账号同步进入同一配置队列；配置文件暂时不可写时保留已提交的账户操作并记录错误 |
| 一个请求尚未上传完配置 JSON | 将锁覆盖到请求读取可能阻塞其他保存 | 读取请求体发生在进入保存队列之前，回归测试验证慢上传不会占锁 |
| 非对象的 Responses JSON 或异常工具结构 | 可能抛出未处理的类型错误 | 返回 400，不调用上游 |
| 无法解析、读取或转换的上游批量响应 | 可能抛出内部错误 | 返回 502，不写入完成历史 |
| 不支持 structuredClone 的浏览器 | 提示词草稿加载失败 | 复用面板的 JSON 克隆回退 |

## 性能与维护

提示词规则在一次改写中只编译一次关键词，所有系统文本块共用；整行规则未命中任何关键词时直接返回。只有发生编辑时才创建新的文本块数组，保留原有 cache-control 和自定义属性。精确替换使用原生替换并预先转义美元符号，避免密集删除时的 split 数组；整块完全删除直接返回空文本。规则顺序、命中次数、修改次数和增长预算沿用原语义。

Responses 非流式响应在 Anthropic→Chat→Responses 之间直接传对象，移除中间的 JSON.stringify、Response 创建、body 读取和 JSON.parse。流式路径继续使用增量转换和背压，不把完整流载入内存。

`src/admin/config.ts` 统一持有保存队列及已保存监听地址，账户同步集中到 `src/admin/account-actions.ts`。修改配置的维护入口和锁使用规则见 [代码分类与维护指南](code-organization.md)。
