## 审查与改动

### 入口职责与启动成本

原 `index.ts` 同时包含参数解析、帮助、OAuth、额度、服务启停、Web 面板、Android 控制和身份配置修复，共 1415 行。TUI 又从入口导入辅助函数，形成 `index → TUI → index` 的动态依赖环。

现入口只保留 16 行引导和兼容导出。CLI 解析先完成命令选择，再加载对应运行模块；版本和帮助命令直接返回，避免初始化 Node fetch dispatcher、代理服务、账号管理和面板。异步命令由分发器等待并统一接住启动错误。

| 模块 | 职责 |
| --- | --- |
| `src/index.ts` | 可执行入口、既有辅助函数兼容导出 |
| `src/cli/args.ts` | 纯参数解析、别名、默认 TUI 与 `--cli` 规则 |
| `src/cli/main.ts` | 按命令加载模块、等待执行和启动错误处理 |
| `src/cli/help.ts` | 命令说明 |
| `src/cli/auth.ts` | 登录、导入、退出、状态、导出和终端 OAuth 流程 |
| `src/cli/billing.ts` | 领取、额度、重置命令及其展示 |
| `src/runtime/serve.ts` | 无界面服务启动、日志接线和关闭 |
| `src/runtime/serve-panel.ts` | 有令牌保护的进程内控制面板 |
| `src/runtime/android.ts` | Android 服务与回环控制监听 |
| `src/runtime/identity-config.ts` | 身份配置修复与 Android 环境默认值 |
| `src/runtime/process-exit.ts`、`log-tee.ts` | 终端退出与共享日志缓冲接线 |

TUI 直接依赖共享模块；生产源码不再反向导入 `index.ts`。拆分后的实现仍计入项目总代码量，入口行数用于说明职责分离。最大的新增实现模块为 305 行。

### 故障转移与套餐判定

- 原服务与 Android 入口单独提供账号列表，默认 TUI 只调用 `createConfiguredAuthManager(config)`，无法发现备用账号。账号列表现在由该工厂统一提供，三个入口共用同一来源；测试仍能显式注入列表。API Key 模式继续由 AuthManager 隔离，不读取账号列表进行轮换。
- 服务启动仍用“JWT 存在即体验套餐”的旧规则。现在复用 `resolveEffectivePlan()`，显式凭据套餐优先，JWT 本身不改变套餐，体验套餐缺少 JWT 时使用编码套餐。备用账号的验证码预热判断也复用同一规则。
- `switchToNextCredential()` 用 `find()` 找到首个可用账号后即停止，删除全部候选账号数组及已经不可达的 API Key 写入分支。可用账号计数使用循环，避免另建筛选数组。返回值与内部缓存继续隔离。

### 身份配置的正确性与文件访问

旧实现用多段正则扫描整份 YAML，存在以下问题：

| 输入 | 原问题 | 当前行为 |
| --- | --- | --- |
| `deviceMid:` 后直接换行 | `\s*` 可能吞掉下一行，把下一项当作非空值 | 生成 UUID，保留下一项 |
| `deviceMid: # 注释` | 注释被当成设备 ID | 生成 UUID并保留注释 |
| 单引号设备 ID | 返回值可能包含引号 | 使用 YAML 解码后的字符串 |
| `identity: { ... }` | 可能再追加一个 identity 块，产生重复键 | 更新原行内映射 |
| 其他章节的 `deviceMid` / `appVersion` | 全局正则可能命中无关字段 | 只操作 identity 路径 |
| 版本值带行尾注释 | 版本比较失败，旧版本没有更新 | 比较解析后的字符串，保留注释 |
| `3..1`、`3.+1`、不安全整数段 | Number 转换可能接受空段等错误格式 | 保留自定义值，不自动升级 |
| 损坏 YAML 或非映射 identity | 原逻辑可能继续写入，扩大损坏 | 抛错并保持原文件字节不变 |

现在使用项目已有的 YAML 文档模型，统一完成读取、校验、修改与原子保存。一次身份修复只读一次，字段需要修改时最多写一次；字段已有效时保持原文件内容不变。配置首次创建仍通过已有模板入口处理。

## 性能验证

对第一轮工作树与当前实现使用相同 esbuild 参数打包，在 Node **v24.22.1** 中分别执行版本和帮助命令。每个场景先预热一次，再启动五个全新进程，取进程启动到退出的中位数；打包时间不计入。

| 命令 | 第一轮 | 第二轮 |
| --- | ---: | ---: |
| `--version` | 136.954 ms | 123.808 ms |
| `--help` | 140.919 ms | 120.924 ms |

启动结果会受机器负载和文件缓存影响，样本较少；这组数据只反映当前环境的 Node 命令启动时间。职责拆分和不再初始化无关运行模块是本轮主要收益，不能从这些数字推导服务吞吐量。原始样本见 [performance-cli-2026-10-26.json](performance-cli-2026-10-26.json)。

复现：

```bash
bun scripts/bench-cli-startup.ts
bun scripts/bench-cli-startup.ts /path/to/first-round-checkout
```

基准需要 Node 可执行文件；可用 `NODE_BINARY` 指定。当前环境使用临时 `tsx` 加载器执行基准 TypeScript，不向项目添加测试运行依赖。
