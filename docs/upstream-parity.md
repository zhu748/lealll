# 上游功能对齐恢复记录

旧工作区的前两轮未提交代码没有可用备份。本次在 `30470f2` 的后台分类成果之上，按第一轮记录中的上游提交 `17933d242621d4482ed1ce11c8eaf938b4e08e78` 重新实现，并以三方合并保留 fork 的既有修改。

| 功能 | 恢复方式 | 保留的 fork 行为 |
| --- | --- | --- |
| 视频和文档输入 | OpenAI、Anthropic、Responses 类型与双向转换；URL 和内嵌数据；工具结果内容 | 图片类型校验、未知内容可见降级、空文本过滤 |
| Responses | 流式失败事件、工具输入解码、输出顺序 | 历史存储、重试和缓存、现有翻译回归 |
| 独立面板 | 可选回环地址面板、强制独立 token、进程内控制分发 | 原 `/admin` 看板、代理密钥和 CSRF 限制 |
| 更新检查 | CLI/TUI 通知、手动检查合并、容器升级提示 | 检查源切换到 `zhu748/lealll`；统一 package.json 版本 |
| 额度展示 | CLI、TUI、Android 同用额度快照；Android 页面和控制命令 | MCP 用量、套餐可用性、领取和重置接口 |
| Android | 上游额度界面及构建脚本 | 现有网络安全配置、控制鉴权、fork 更新地址 |

三方合并中的冲突逐项处理：保留多账号 AuthManager、代理池初始化、凭证异步清理、无登录启动看板、配置路径传递与有界日志落盘退出。第三轮的后台模块布局和公开入口不回滚。

发布预检发现原 SSE 批量测试会统计进程内所有流的 enqueue。改为观察该客户端实际收到的批次，严格检查 25 条日志一次发送且顺序完整，消除无关流造成的误报。

第二轮可靠性与性能优化见 `optimization-review.md`。当前恢复实现的测试和构建结果会重新验证，不沿用丢失工作区的历史测试数字。
